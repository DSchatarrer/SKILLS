# Reproducción experimental: protocolo crítico

## Diseño antes de ejecutar

1. Extraer de tablas originales métricas, unidades y dirección (mayor/menor es mejor), incertidumbre y N semillas.
2. Registrar hash o versión de dataset, licencia, preprocesamiento, deduplicación, split train/valid/test, transformaciones solo aprendidas en train y evaluación sin fuga.
3. Registrar arquitectura, inicialización, loss, optimizador, scheduler, batch size, epochs/pasos, gradient clipping, precision, checkpoint selection.
4. Capturar hardware, consumo estimado, versiones de framework/CUDA, acelerador, sistema operativo y determinismo garantizado/no garantizado.
5. Establecer rangos de equivalencia ANTES de ejecutar. Una diferencia estadísticamente indistinguible no significa equivalencia sin un margen prefijado.
6. Ejecutar smoke test y baseline trivial. Identificar entrenamiento que memoriza solo unas muestras para aislar bugs de pipeline, sin llamarlo reproducción de paper.
7. Ejecutar configuración descrita por los autores y semillas múltiples si es viable. Evitar elegir retrospectivamente solo la mejor seed.
8. Guardar métricas crudas, logs, intervalo/desviación, comandos y límites computacionales.

## Evaluación del resultado

- **Replicación de código**: correría el mismo código y los mismos datos; **reimplementación**: código independiente y protocolo equiparable.
- El resultado de una parte NO implica reproducir el resto.
- Explicar ablations: qué cambia y por qué hay evidencia para cada claim.
- Comparar estrategias, hardware y versiones con sensibilidad; reportar también fallos.
- Si el dataset está restringido, marcar bloqueo e implementar solo módulos verificables sin atribuir scores al paper.
